A snurra document is plain text that calculates as you type. Write what you know, say how the rest follows from it, and hand the document to someone who can change the numbers and watch the answers move.

Getting started

Every line is name = expression, or just an expression. Everything after # is a comment.

# Mortgage
loan = 8_000_000
interest = 3%
amortization = 2%

mortgage = (loan * amortization + loan * interest) / 12   # per month

A line whose right side is just a value (loan = 8_000_000) is an input: it appears in the Inputs panel as a field anyone can change. Any other line is calculated, and its result shows next to it and in the Results panel. There is no run button; the whole document recalculates on every edit.

You don't have to name everything. A line that is only an expression, like 3 + 4 or loan * interest, is calculated and shown as a result next to the line, like on a calculator. It isn't stored, so other lines can't use it; give it a name if you need it. A line that starts with a name and = is always an assignment, so to compare on a line of its own, put the comparison in parentheses: (a = b).

Try Help → Examples in the header to open a ready-made document. Choosing one replaces what you have, and undo (Ctrl or Cmd+Z) brings it back.

Line numbers are hidden, since an error is marked in red and the problem list takes you to it. Turn them on under Settings in the header.

Values and names

Kinds of value

KindWrittenNotes
Number1250.50, 8_000_000, 3%. is always the decimal point; _ is for readability; 3% means 0.03
Text"Sales"Compared exactly: "Sales" is not "sales"
True/falsetrue, false

Duration30 days, 1 monthNeeds a space between number and unit

Arithmetic is exact decimal arithmetic, never floating point, so 0.1 + 0.2 is 0.3. Results show up to two decimals. A document means the same on every computer, in every locale.

There is no scientific notation (1.3e8) and no suffix like 3M; write 130_000_000.

Names

  • Letters (including å, ä, ö), digits and _. No spaces, and no starting with a digit.
  • Case does not matter: Loan and loan are the same name. The first spelling is the one shown.
  • A name can only be used on lines below where it is defined. Using it earlier tells you which line to move.
  • Each name can be defined once. Words that mean something in the language (where, by, table, sort, with, row, prev, function names, …) can't be names.

Operators and functions

An expression can go on over several lines: a ( that is not closed on its line goes on below it, on lines indented more, until it is closed. A comment may end any line, and a hint (@hidden) goes at the end of the last one. 

weight = 3

shipping = if(
    weight < 1, 20,    # small parcel
    weight < 5, 45,
    90
  )

The closing bracket may be in the column of the statement, but every other line has to be indented, and a blank line ends an unfinished expression: that is what keeps a forgotten ) from taking the next statement with it. The error says which bracket was left open.

+ - * /, ^ for power, and parentheses. Precedence is the usual one, and -2^2 is −4. There is no % operator: 3% is just the number 0.03, so 100 + 20% is 100.2, not 120. For 20 percent more, write 100 * (1 + 20%).

FunctionWhat it does

part(t, from, n), split(t, sep, n)Cut text: n characters from character from (negative counts from the end), or piece n between separators

Function names are case-insensitive. sum(5) is an error: with one argument, the aggregate functions need a column.

Conditions

Compare with =, <>, <, >, <=, >=. At the start of a line = assigns; anywhere else it compares. Combine with and, or and not. 

income = 42_000
loan = 600_000
ok = income * 5 > loan and not (loan = 0)
fee = if(ok, 0, 500)

if, and and or only evaluate what they need, so if(x = 0, 0, 1 / x) is safe when x is 0.

Dates

A date is written 2024-03-01. There is deliberately no today(), since that would make the same document mean something different tomorrow. Make today an input instead and let the reader set it. 

today = 2024-03-15
invoice_date = 2024-02-20
due = invoice_date + 30 days
days_late = if(today > due, today - due, 0)
quarter = floor((month_of(due) + 2) / 3)
  • date - date is a number of days; date + 30 and date + 1 month are dates.
  • Month arithmetic keeps the day, or clamps to the end of a shorter month: 31 January plus 1 month is 29 February (2024).
  • Functions: year_of, month_of, day_of, weekday_of (1 is Monday), add_months(d, n) and month_start(d).
  • month_start(d) is the usual key for grouping by month. Such dates are shown as a month name and year.
  • weekday_of(d) is shown as a day name (Mon, Tue, …) but is still the number 1 to 7. Adding or subtracting whole days keeps it a weekday while it stays between 1 and 7: Friday + 1 is Saturday, but Sunday + 1 is a plain 8. Multiplying and dividing give plain numbers.
  • A date never equals text: d = "2024-01-01" is an error. Write it without quotes.
  • Impossible dates (2023-02-29) are errors, never rolled over to the next month. 2024 - 03 - 01 with spaces is subtraction.

Lists

Commas make a list. Everything that works on one value works on every item.

weights = 60, 70, 80
h = 1.8
bmi = weights / h / h
tall = weights where weights > 65
total = sum(weights)

Two lists combine item by item if they have the same length; a list and a single value always combine. A list is an input when it is written out with values only, so it shows in the form.

Tables

name = table followed by indented lines: the first is the column names, the rest are rows. Cells are separated by commas. Leave a cell empty for "no value". 

budget = table
  dept,  limit
  Sales, 50000
  Ops,   30000
  Admin,
  • budget.limit is a whole column. Columns of the same table combine row by row: budget.limit * 1.25.
  • Text with a comma in it is quoted: "Smith, John". A column is numbers if every filled cell is a number, otherwise text.
  • A blank is not zero. Totals skip blanks, and arithmetic with a blank gives a blank.
  • A row with the wrong number of cells makes the whole table an error, so a total never silently skips data.
  • Tables are inputs: in the Inputs panel they are an editable grid. Tab and Enter move between cells, and typing in the empty last row adds a row.
  • Columns line up automatically as you type. The spaces are only for reading.
  • table of weights, bmi builds a table from lists of the same length.

A table with many columns can be narrowed to the ones worth showing: keep names the columns to keep, and drop names the ones to leave out (use one or the other, not both). keep gives the columns in the order you write them, so it also reorders, and as renames a column. 

wide = table
  dept,  limit, owner, phone,    level
  Sales, 50000, Anna,  555-0101, 2
  Ops,   30000, Bo,    555-0102, 3

overview = wide keep dept, limit
no_contact = wide drop owner, phone
renamed = wide keep dept as team, limit as cap

keep and drop go in a chain after where and with. Before sort and limit the sort sees only the columns that are left: top = wide keep dept, limit sort limit desc limit 1. After them, once, they only choose what is shown, so a column that was needed for the order can go: top = wide sort limit desc limit 1 keep dept. Use table of to build a table from lists, which keep cannot do.

A table with a date (or month, or whole number) column that has gaps can be given a row for every step with complete: daily = sales complete. The first column is the index (it is also the x axis of a chart), so use keep to put another column first. The new rows are blank in the other columns, so a chart of it has an even x axis. Each value of the column must appear only once.

A column whose name starts with _ and a letter is a private step of the calculation: _num_done = count(...), then progress = concat(_num_done, "/", _num_total). The columns after it can read it, but it is not a column of the table, so tables made from it never carry it. The editor still shows it (dimmed, under "Show hidden") so you can check the step. Use @hidden instead for data that must stay in the table but out of sight.

The steps of a chain can go on the lines below the statement, one on each line, indented. The lines are joined, so this means the same as writing them all on one line: top = expenses, then sort amount desc and limit 2 per month_start(date) on the next lines. A line counts as a step if it starts with where, by, with, keep, drop, complete, rank, sort or limit and is not a name being defined (limit = 5 is a column). A blank line ends the steps.

A by is a step like the others: the with right after it says what each group gives, and the steps after that see the finished table, as in fig = expenses by date across descr with total = sum(amount) complete.

Filtering and lookups

where keeps the rows (or list items) that match. lookup is the same, but insists on exactly one match, and gives a single value or a row. 

budget = table
  dept,  limit, owner
  Sales, 50000, Ana
  Ops,   30000, Ben

expenses = table
  dept,  amount
  Sales, 1200
  Ops,   400
  Sales, 800

big = expenses where amount > 500
ops_limit = lookup budget.limit where budget.dept = "Ops"
travel_limit = lookup budget.limit where budget.dept = "Travel" otherwise 0
b = lookup budget where budget.dept = "Sales"
sales_owner = b.owner
n_big = count(expenses.amount where expenses.amount > 500)
  • A where runs to the end of the line. Parenthesise it to use it inside a bigger expression.
  • No match, or more than one, is an error that says which value was missing or ambiguous. Matching is exact.
  • Add otherwise to a single-value lookup for a fallback when nothing matches: lookup budget.limit where budget.dept = "Travel" otherwise 0. Several matches, or an error in the condition, are still errors. The fallback is taken as written (0 is a plain number, 0% a percent), and it is not available when looking up a whole row.
  • If a bare name could mean a column of two tables, or a column and one of your own names, you get an error that lists the candidates. Write table.column to be explicit.

New columns: with

with name = expression adds a calculated column to a table and keeps every row, in the same order. Inside it, column names mean "this row's value". For several columns, separate them with commas (with half = a / 2, double = a * 2) or put each with on a line of its own below the table; a later column can use the ones added before it. The same lines can sit at the end of a table's own rows, after the last row: with total = a + b. Those columns are worked out, not typed, and with is the only step that goes there. 

expenses = table
  dept, amount
  Sales, 1200
  Ops, 400
  Sales, 800

total = sum(expenses.amount)
shares = expenses
  with share = amount / total
  with pct = round(share * 100, 1)

Because with works one row at a time, a total over the same table has to be a line of its own, as total is above. row is the row number, prev the value on the row before, and prev(n) goes back n rows, which is what a calculation that builds on the row before needs: balance = if(row = 1, start, prev * (1 + rate) + deposit). For a running total, see below.

Running totals and totals per group

Inside a with, the thing an aggregate adds up can say which rows it takes. per category keeps the rows of the same category as this row, and running keeps the rows up to this one, in the order of the table. They go after the value, running first, and a where goes last. 

expenses = table
  category, amount
  rent, 12500
  food, 2300
  food, 800
  rent, 12500

left = expenses
  with spent = sum(amount running per category),
       share = amount / sum(amount per category)

sum(amount per category) is the total of the row's category on every row, so it gives a share. A row that fails a where still shows what the other rows add up to. Sort the table in an earlier statement if the order matters.

Grouping: by

table by key makes one row per distinct key. The with right after it says what each group gives, columns separated by commas; inside sum, avg, min, max, count and friends you see the group's source rows. A with after that works on the finished table, one row at a time. 

expenses = table
  dept,  amount
  Sales, 1200
  Ops,   400
  Sales, 800

budget = table
  dept,  limit
  Sales, 50000
  Ops,   30000

per_dept = expenses by dept
  with total = sum(amount),
       limit = lookup budget.limit where budget.dept = expenses.dept,
       left = limit - total
  sort total desc
  • Several keys are comma-separated. A computed key needs a name: by month = month_start(date).
  • Rows come out sorted by the keys. A sort total desc step sorts by something else (asc is the default).
  • Groups match exactly, so Sales and sales are two groups. A blank key becomes a visible (blank) group.
  • Using a column that has many values per group outside an aggregate is an error, with the fix in the message.

Sorting and limiting

sort and limit are steps at the end of a chain. limit 3 keeps at most three rows: the first three, in whatever order the table has. Sort first and you get a top list. 

utgifter = table
  vem,  belopp
  Anna, 400
  Bo,   900
  Cleo, 150
  Dan,  700

top_spenders = utgifter by vem
  with total = sum(belopp)
  sort total desc
  limit 3

biggest = utgifter
  with double = belopp * 2
  sort belopp desc
  limit 2
  • The result says "3 of 4 rows" so a reader can see that rows were left out. Anything calculated from it afterwards only sees the kept rows.
  • The number can be a name, so a reader can change how many to show: limit shown. It must be a whole number, 0 or more.
  • Rows that tie at the cut-off stay in the order they had, so the result never changes between runs.
  • After a with, the sort happens last: row and prev still follow the original order, and the sort can use any column.
  • limit is only a keyword at the start of a line with no =, so it still works as a column name.

When all you want is the top of a table, no by is needed: sort and limit can end any table expression, on one line. 

utgifter = table
  vem,  belopp
  Anna, 400
  Bo,   900
  Cleo, 150
  Dan,  700

top2 = utgifter sort belopp desc limit 2
big = utgifter where belopp > 300 sort belopp, vem
  • They come last in the chain, sort first: only keep or drop, once, can follow them, not even a where. Either one can be left out.
  • The keys can be several, with asc or desc, and expressions over the columns, and so can the number.

Series

When each row builds on the one before (savings, loans, schedules) use a series: a counter and a range with .., then its columns in a with like any table's. 

start = 10_000
rate = 5%
deposit = 1_000

growth = year 1..30
  with balance = if(row = 1, start, prev) * (1 + rate) + deposit,
       interest = if(row = 1, balance - start, balance - prev.balance)

final = last(growth.balance)

Each row here is the balance at the end of that year, so the first one already has a year of interest and a deposit in it. prev is this column in the previous row, prev.name any column of the previous row, also one further down the list. A with straight after a range works out its columns one row at a time. Reaching before the first row is an error, which is why the first row is written out with if(row = 1, …). prev_or(x) is shorthand for if(row = 1, x, prev), so the balance above can be prev_or(start) * (1 + rate) + deposit. prev_or(x, n) is if(row > n, prev(n), x): x in the first n rows, then the value n rows back. Series have at most 10,000 rows, and the result is an ordinary table.

Pasting data

Paste a table copied from Excel, Google Sheets or a bank export onto an empty line, and it becomes a data = table in the document's own spelling. Numbers like 33 333,33 or 1.234,56 become 33333.33 and 1234.56; dates like 31.12.2024 become 2024-12-31. Pasting below a table's last row adds rows to it.

snurra never guesses silently. If a value is ambiguous (1,234, or 03/04/2024) and the rest of the column can't settle it, the whole column is pasted as text, and a comment above the table says why. Summing a text column is an error, so nothing goes wrong unnoticed.

Hiding lines

Put @hidden at the end of a line, before any comment, to keep it out of what the reader sees. Hidden inputs become constants the reader can't change; hidden calculations are left out of the results. 

price = 100
moms = 25%                       @hidden
brutto = price * (1 + moms)      @hidden  # shown to the author only
total = brutto * 2

A hint never changes what a line means. An error is never hidden. The editor shows hidden values dimmed behind a "Show N hidden" switch, and a reader is told that something is hidden.

Notes for the reader

@note adds a sentence of free text that the reader sees with a line: under an input, beside a result, and under the name of a table. It goes at the end of a statement or, for a longer text, on a line of its own directly above it. The text is the rest of the line up to a # comment, so it needs no quotes. 

@note What one unit costs, before VAT
price = 100

total = price * 1.25   @note The price with VAT

Put the text in quotes if it has a # or an @ in it, or if another hint follows it: @note "Costs # extra" @hidden. A note goes on a whole statement, not on a column of a block, and a @hidden line shows no note.

Offering choices

Put @options and some more values at the end of an input to let the reader try them with one click. The values are shown as buttons instead of a field, and clicking one rewrites the value in the line. 

interest = 3%          @options 2%, 4%
price = 4_000_000      @options 5_000_000
cost = price * interest

The value on the line is one of the choices, so the options don't repeat it. The buttons are in order: numbers by size, dates and durations by time, true before false, and text alphabetically (capitals don't matter). Picking a button swaps it with the value on the line, so the list is always the other values. The options are plain values of the same kind as the input, and the hint only goes on an input that is a single value (not a list or a table). The buttons are in the Inputs panel; Results view shows only the answers, so it has none.

Charts

Put @chart line or @chart bar on a line that makes a table, and the table is drawn as a chart above its grid. The first column is the x axis; every other column of numbers is a line or a set of bars. 

start = 10_000
rate = 5%
deposit = 1_000

growth = year 0..30
  with balance = if(row = 1, start, prev * (1 + rate) + deposit)  @chart line

@chart bar suits categories, such as the groups of a by. The hint goes at the end of the last line of the statement that makes the table. 

expenses = table
  dept, amount
  Sales, 1200
  Ops, 800
  Sales, 300

per_dept = expenses by dept
  with total = sum(amount)  @chart bar

There are no chart settings. The axis always starts at zero, a blank cell is a gap and never a zero, and a column marked @hidden is left out. Columns on very different scales share one axis, so hide the small one or chart a keep with just the columns to compare.

Like every hint, @chart never changes what a line means: the table has the same values with or without it. It is an error on anything that isn't a table, on a step line before the last, or when no column besides the first holds numbers, and the message says so. Hovering a point or a bar shows its value. The table under a chart starts closed, with its size shown; click its arrow to see every number, and your choice is remembered.

Sheets

A long document can be split into sheets. Put @sheet on a line of its own, with a name if you like, and everything below it, up to the next @sheet, belongs to that sheet: 

@sheet Budget
income = 5000
rent = 1500

@sheet Summary
left = income - rent

With two sheets or more, the inputs and results show a tab for each, and only the open sheet's lines. The code still shows everything. Sheets don't separate names: income can be used on any sheet, so a summary sheet can pull from the others. Lines before the first @sheet form a sheet of their own, an unnamed sheet is called "Sheet 2" and so on, and repeating a name carries on that sheet. A problem on any sheet shows in the problems badge at the top, and clicking it opens the sheet it is on.

Errors

A mistake on one line is shown on that line, in plain language, and never stops the rest of the document. Lines that depend on a broken line show the same problem, so a wrong number is never shown quietly. While you type, new errors are held back for a moment so half-written lines don't flash red.

Documents always finish: there are no loops or recursion beyond the bounded series, and nothing in a document is ever run as code.

The editor

  • Code shows the editor alone, with results beside each line, and calculated tables drawn as grids under their statements. Code & results adds the Inputs and Results panels. Inputs & results hides the code and leaves only the inputs and results: that's the view for someone who just wants to use the document. Results shows only the results, with no code and no inputs, for someone who only cares about the answers.
  • Writing name = number adds a field to the Inputs panel. Hovering a field or its line links the two.
  • Your document is saved in your browser as you type.
  • The Tutorial item in the Help menu opens a list of chapters; pick one to start. It teaches the language in five short chapters, each in a document of its own. A bubble gives you something to do; when you have done it, press Next step: the lines so far lock and the next task appears below. A chapter ends by inviting you to the next, which starts afresh (some start with a few lines already written). Your own document comes back when you leave.
  • Autocomplete offers your names and the functions, and a table's columns after table..
